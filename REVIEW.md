# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Global / Startup | Missing database indexes on both collections. | Duplicate `emp_code` and `(emp_code, date)` can be inserted; explain plans show `COLLSCAN` and poor performance. | Added `ensure_indexes()` creating unique indexes on `employees.emp_code` and `attendance_logs.(emp_code, date)`, along with query and sort indexes. |
| 2 | `health()` (L73-74) | Fake health check returning static `{"status": "ok"}` without testing MongoDB connectivity. | `GET /health` returns 200 even when MongoDB is offline or disconnected, violating readiness probe requirements. | Added `client.admin.command("ping")` inside a try-except block, returning HTTP 503 on failure. |
| 3 | `create_employee()` (L79-83) | Check-then-insert race condition (`find_one` followed by `insert_one`). | Concurrent POST requests with the same `emp_code` both pass the check and create duplicate records. | Rely on database unique index on `emp_code`; catch `DuplicateKeyError` and return HTTP 409. |
| 4 | `EmployeeIn` (L53-61) | Missing schema validations on `emp_code`, email, and shift times. | Invalid `emp_code` format (e.g., `XYZ123`), invalid emails, or `shift_start == shift_end` pass validation with 201 instead of 422. | Added regex pattern constraints (`^EMP\d{4,6}$`, email regex) and a validator asserting `shift_start != shift_end`. |
| 5 | `list_employees()` (L93) | Off-by-one pagination bug: `skip = page * page_size`. | `page=1` with `page_size=20` skips records 1–20, returning records 21–40 instead. | Corrected offset formula to `skip = (page - 1) * page_size`. |
| 6 | `list_employees()` (L94) | Collection-wide count ignoring filters: `db.employees.count_documents({})`. | `GET /employees?department=Engineering` returns the total count of the entire collection instead of filtered records. | Updated count to `db.employees.count_documents(q)`. |
| 7 | `punch_in()` (L101, 113) | Missing employee lookup validation causes 500 error. | Punch-in for a non-existent `emp_code` raises unhandled `TypeError` when accessing `emp["shift_start"]`. | Added verification `if not emp: raise HTTPException(404, "Employee not found")`. |
| 8 | `punch_in()` (L104-105) | Check-then-insert race condition on attendance record. | Concurrent simultaneous punch-ins for the same employee on the same date produce multiple records. | Enforced compound unique index `(emp_code, date)`; catch `DuplicateKeyError` to return HTTP 409. |
| 9 | `punch_in()` (L103) | Attendance date assumes local date, ignoring R1 overnight shift logic. | Punching in at 01:00 IST for a 22:00–06:00 shift incorrectly assigns the record to the current calendar date instead of the previous day's shift. | Calculated IST calendar date and subtracted 1 day if punch-in IST time is before `shift_end` for overnight shifts. |
| 10 | `compute_late_minutes()` (L35-37) | Uses naive datetime arithmetic, integer division truncation, and fails across day boundaries. | Punch-in at 09:40:01 with grace period gives incorrect or negative values when crossing day boundaries. | Replaced with IST timezone-aware comparison against shift start, strictly checking `diff_seconds > 600`, and applying `math.floor(diff_seconds / 60)`. |
| 11 | `compute_work_hours()` (L41) | Python's standard `round()` uses round-half-to-even (banker's rounding). | `2.125` rounds to `2.12` instead of `2.13`, violating rule R4/R8 (must be half-up). | Implemented `round_half_up()` using `decimal.Decimal.quantize(..., rounding=ROUND_HALF_UP)`. |
| 12 | `compute_overtime()` (L46-47) | Missing 30-minute minimum threshold (R3) and overnight shift handling. | Punch-out 10 minutes after shift end returns 10 minutes overtime instead of 0; fails overnight shift midnight transitions. | Added condition requiring `diff_seconds >= 1800` before flooring minutes, and properly projected next-day shift end for overnight shifts. |
| 13 | `list_attendance()` (L144-147) | Full collection memory load, sorting and slicing in Python. | On large collections (~100k docs), pulls all rows into RAM, causing extreme latency, memory exhaustion, and slow responses. | Replaced with database-level query: `cursor.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`. |
| 14 | `punch_in()` & `list_attendance()` (L119, 149) | Internal `_id` transformed into unauthorized `id` field. | Responses include an extra `id` field contrary to the OpenAPI schema contract. | Omitted `id` and internal `_id` entirely, strictly conforming to `AttendanceRecord`. |
| 15 | `punch_in()` & `create_employee()` (L82, 102) | Non-standard timestamp handling and missing whole-second truncation. | Milliseconds fractions are retained rather than truncated to whole seconds (R1); accepts invalid integer values or strings. | Validated EpochMillis integer bounds and truncated to whole seconds via `(ms // 1000) * 1000`. |

### What was examined and decided was NOT a defect
- **`emp_code` as primary business key**: Kept as a customer-provided string rather than MongoDB `_id` or auto-incrementing integer, as explicitly specified by the system design and domain contract.
- **Calendar dates stored as `"YYYY-MM-DD"` strings**: Storing calendar dates and shift times as strings prevents accidental timezone conversion and drift when querying across distributed systems.
- **Derived fields stored directly on attendance documents**: Storing precomputed derived fields (`work_hours`, `late_minutes`, etc.) is an intentional denormalization pattern to allow fast analytics aggregation without recalculating on every query.
